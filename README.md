# X Reply Copilot

[English](README.en.md) | 中文

一个直接运行在 X 网页里的 Chrome / Edge Manifest V3 扩展。它支持筛选与自动评论，也提供与评论设置完全隔离的自动发帖模块。

## 界面语言

浮窗标题旁的 `EN` / `中` 按钮可立即在中文和英文之间切换。语言选择按浏览器配置文件保存，并同步到已打开的其他 X 标签页。切换只影响扩展自己的标签、按钮、任务状态和提示；不会翻译或修改 X 页面内容、帖子、固定内容、提示词、方案名、图片文件名或 API 服务商返回的原始错误详情。

## 自动发帖（v0.16.0）

面板新增独立的“自动发帖”页，与自动评论使用不同的内容池、图片库、数量、间隔和任务进度。

- 支持指定固定帖子或 AI 生成帖子。
- 固定内容可按顺序轮换或随机选择。
- 发帖图片从专用图片库按概率随机选取，也可能不带图片。
- 支持固定间隔和随机时间区间。
- 支持暂停、继续、结束，并在页面跳转后恢复任务。
- 支持公开时间线和指定 X 社区。社区模式填写完整社区链接或数字 ID；扩展只会在对应社区路径中尝试发送，无法确认社区时会暂停。

API Key、API 地址和模型仍与评论功能共用；所有发帖正文、图片和任务状态均独立保存，不会混入评论设置。

## 安装

1. 打开 `chrome://extensions`（Edge 使用 `edge://extensions`）。
2. 开启“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择本项目文件夹。
4. 打开或刷新 `https://x.com`，右上角会出现浮窗。
5. 在“设置”里填写 API Key、API 地址和模型。

## 使用

1. 在 X 搜索页、主页或账号页滚动，让网页加载所需帖子。
2. 在浮窗设置作者账号、关键词、最低点赞和最近天数。作者必须填写 `@` 后面的账号 ID（例如 `Davincij15`），不能填写显示名称。
3. 点击“扫描当前页面”。
4. 对结果执行“AI 分析”或“生成回复”。
5. 点击某条建议的“填入”，检查 X 回复框内容后手动发布。

## 回复模式

- 定向回复：在“设置”中填写自己的运营提示词。AI 以提示词规定的项目观点、表达目标、语气和禁区为主，原帖只作为自然衔接的上下文。
- 原帖回复：AI 主要围绕原帖内容生成普通互动回复。

定向提示词示例：`重点表达比特币长期主义；自然提到项目名；不要谈价格；不要承诺收益；语气坚定；使用英文；每条 20 词以内。`

设置中的“单条回复字符上限”最高为 280。AI 提示和扩展输出会执行双重限制；每条建议会显示实际字符数。点击“填入”会通过一次原生编辑动作替换全部内容，并验证 X 的回复按钮已经启用；只有文字显示但按钮仍不可用时会明确提示失败。

## 批量自动回复

“生成建议数量”可设置为 1–10；结果顶部可直接设置“本次回复”1–2000 条；自动发送间隔最低 1 秒。可以选择按浏览量、点赞数或日期排序。点击“开始”后，扩展会依次生成、填入并公开发送，不再执行单独的 AI 分析或 AI 评分。运行中可以暂停、继续或结束。自动发送处理结果列表中已经采集并通过排除条件的帖子。

批量任务会保存在扩展本地存储中，并在同一个标签页依次进入帖子详情页完成回复；不会因为 X 的虚拟列表移除旧帖子而新开失控页面。详情页顶部会显示任务进度和“停止任务”，完成或停止后自动返回原搜索页。

发送间隔支持固定时间和随机区间两种模式。随机模式会在每次发送后从最小值到最大值之间重新抽取一个整数秒数。等待间隔时会并行预生成下一条回复，因此除第一条外，通常无需在进入帖子后再次完整等待模型响应。

扩展会保存最近 5000 条由自动任务成功处理的帖子 ID，并在结果中标记“已回复”。历史记录按 status ID 归一化，`x.com`、`twitter.com` 或附带不同查询参数的同一帖子不会被当成不同帖子；旧版保存的 URL 会在加载时自动迁移。“允许再次回复已回复帖子”默认关闭；未开启时，每次发送前还会重新读取本地历史并检查当前账号是否已出现在回复区。页面检查依赖 X 当前加载出的回复，本地历史判断更稳定。

回复内容来源支持“AI 生成”和“指定固定内容”。指定内容模式不调用 AI；多条内容之间用一个空行分隔，可以按顺序轮换或每次随机选择。回复详情会显示来源标签，避免与 AI 生成内容混淆。

批量任务对单条失败采用跳过继续策略：生成失败、回复框未加载或发送按钮暂时不可用时，只记录该条为“已跳过”并进入下一条，不会立即退出整个任务。任务进度分别显示已发送和已跳过数量。

批量发送不使用浮窗二次确认，也不依赖可能被 X 页面拦截的系统确认弹窗；点击“开始”会直接按当前保存设置创建任务，启动异常会直接显示在批量控制栏中。

详情页和弹窗回复框使用不同的页面结构，扩展会同时识别 `tweetTextarea_0` 自身可编辑和其子元素可编辑两种形式。自动填入会等待回复框最长 12 秒，并在 X 未接受第一次输入时重试一次。

字符上限、自动回复数量以及固定/随机发送间隔属于公共自动化设置，在 AI 生成和指定固定内容两种来源下都会显示并生效。只有回复模式、生成建议数量和定向提示词属于 AI 专属设置。

自动任务会把进度、候选列表、当前序号和下一次执行时间保存到扩展本地存储。页面跳转或普通的后台标签页节流后，会由扩展后台心跳恢复；同一任务只允许启动它的标签页推进。达到每小时/每日上限或不在活跃时段时，任务栏会显示触发的运行保护、当前用量、实时剩余时间和精确的自动恢复时间；若多项保护同时生效，以最晚允许发送的时间为准。等待状态会持久化，并在刷新页面或后台恢复后重新校验，不会重复发送。循环任务在采集、评论或轮次等待阶段暂停时会保留当前轮次、已采集结果和处理位置，点击继续后从原位置恢复，不会新建一轮。填入失败、发送按钮暂不可用或发送结果一时无法确认时，会自动重试当前帖子，超过重试次数后跳过并继续。只有检测到无法安全清除的 X 草稿时才暂停，避免触发离站确认或重复发送。

自动任务运行期间，进度、暂停和结束按钮会与导航标签一起固定在浮窗顶部；向下滚动筛选、结果或设置内容时仍保持可见。

任务栏按钮使用独立的捕获事件，不依赖下面内容区的普通事件冒泡。“继续”会在执行循环丢失时主动重新启动持久化任务；“结束任务”会先立即删除任务状态并停止循环，再清理当前草稿，避免因 X 编辑器响应慢而表现为按钮无效。

关键词自动采集以 X 搜索语句中的 `min_faves` 和 `since` 结果为准，不再根据可能尚未完整渲染的本地数字进行第二次过滤；启用“严格要求关键词出现在帖子正文”后，只有作者名称、用户名或简介包含关键词的结果会被排除。英文和数字关键词使用完整词匹配，例如 `BTC` 不会误命中 `BTCC`；多个关键词仍采用命中任意一个的 OR 逻辑。本地还会执行 Reply、Quote 和已回复状态排除。“最多采集条数”和循环模式的“每轮最多采集”按排除后的有效结果计数，被排除的帖子只计入扫描统计、不占用采集额度。采集会自动滚动并持续保存去重后的帖子，直到有效结果达到上限；页面底部连续稳定且没有新帖子时会判定已经触底，处理完现有候选后自动结束循环。空轮次提示会显示扫描数量和各类排除统计，便于检查筛选条件。

指定固定内容使用动态表单保存：每条回复有独立输入框，通过“＋ 在顶部添加新内容”新增并可单独删除，不再用空行分隔。列表支持展开/收起，并按新内容在上、旧内容在下显示；底层保存顺序仍保持旧到新，避免升级后改变原有顺序轮换逻辑。旧版本保存的分隔文本会在加载时自动转换为多条表单记录。

评论和发帖配置方案在下拉框中选中后会立即加载，不需要再点击“加载方案”。加载时“方案名称”输入框会同步为当前方案，编辑后保存只会覆盖该名称对应的方案；要新建方案时填写一个新的方案名称再保存。评论方案会保存自己的评论图片库，发帖方案会保存自己的发帖图片库，切换方案时图片和使用概率会一起切换。

指定发帖内容支持批量导入。粘贴以 `1.`、`2.`、`3.`（也支持 `1、`、`1．`、`1)`）开头的编号模板后，每个编号到下一个编号之间会解析为一条帖子，正文、合约地址等内部换行会保留。批量内容会追加到已有列表，并自动忽略完全重复的帖子。

X 的可编辑回复框可能只保存多行粘贴内容的最后一行。扩展发送指定内容前会把内部换行合并为空格，并在点击发送前核对回复框完整文本；内容不一致时会阻止发送、重试并最终跳过，避免只发布合约地址或末尾片段。

由于 X 对部分 Emoji 和 Unicode 使用加权字符计数，自动发送采用最高 270 个普通字符的安全上限。填入成功必须包含待发正文的全部非空白字符，零宽占位符或仅有图片不会再被误判为成功；添加图片后还会再次核对文字，必要时在同一编辑器恢复。重试前会先清空第一次输入并留在当前页面重试；草稿无法安全清空时任务会暂停，不会刷新或跳转，从而避免尾部重复以及浏览器的“是否离开网站”提示。

进入帖子详情页后，自动任务会先等待目标帖子或回复编辑器真正加载，最长 30 秒。加载超时会刷新当前帖子并最多重试两次，此阶段不计入“已跳过”；只有连续加载失败后才跳过，避免在 X 仍显示转圈时误报填入失败。

每篇帖子只允许执行一次内容插入。插入前必须确认回复框已经清空；插入后内容不完整或按钮不可用时会清空并跳过，不再进行第二次插入，避免两份回复叠加。

固定和随机间隔最低支持 1 秒，保存值会直接同步到任务。点击“开始”即创建自动任务，不再要求浮窗内二次确认。填入阶段会忽略 X 的零宽占位符，并要求编辑器包含待发正文的全部非空白字符；发送按钮仅作为附加条件，不能因图片使按钮可用就误判为正文已填入。扩展会依次尝试原生文字输入、HTML 输入、粘贴事件和 DOM 输入事件，以兼容 X 不同版本的编辑器。熔断按最终失败的帖子而非单次重试计数，人工点击“继续”会清除旧的失败计数。若失败后草稿无法清空，任务会停留在当前页等待人工清空，不会导航并触发浏览器离站确认。

回复框完整性改为内容覆盖率判断：实际内容长度需在预期的 70%–130% 之间，且至少覆盖 75% 的有效词语，同时 X 发送按钮必须可用。该规则允许 X 添加内部回复标记和 Cashtag 结构，但会拦截只有末尾地址的残缺内容以及两份内容叠加的重复回复。

“按条件打开 X 搜索”会严格根据当前输入生成搜索语句：必须真正填写作者账号或关键词，只有点赞和日期时不会执行全站宽泛搜索；关键词为空时不会自动补入 Bitcoin；作者会转换成 `from:账号`；点赞、日期、Reply 和 Quote 条件只按当前设置加入。输入框中的灰色文字只是示例，不是实际内容。

## 当前边界

- 只读取页面 DOM 中已经加载的帖子，不调用 X 私有接口，也不会后台无限抓取。
- X 修改页面结构后，`content.js` 中的选择器可能需要更新。
- 点赞数、Reply、Quote 的识别基于当前网页可见信息，属于尽力识别。
- API Key 存储在当前浏览器的扩展本地存储中；生产团队版建议改为自有后端代理和成员鉴权。
- API 请求超过 45 秒会自动停止并显示错误，不会一直停留在加载状态。
- 请控制操作频率并遵守 X 的自动化规则。当前版本坚持人工确认发布。
